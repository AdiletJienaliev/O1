## 🏰 Игра

Вы играете за **полководца** — героя ближнего боя от третьего лица — и одновременно командуете
**армией, которую сами купили**. Матч решает центральный флаг: удержите его дольше остальных —
победили. Всё остальное на карте существует для того, чтобы удерживать было тяжело.

| Опора | Как это играется |
|---|---|
| **Герой и армия в одних руках** | Вы сами деретесь в ближнем бою и параллельно отдаёте отряду один из четырёх приказов — *стоять, за мной, в атаку, защита*. |
| **Флаг — это часы** | Время на центральном флаге и есть счёт. Тай-брейки идут по цепочке: захваты флага → захваченные базы → убитые юниты. |
| **Аванпосты меняют карту** | За каждый захваченный аванпост даётся улучшение на выбор: *снабжение* (доход и слоты гарнизона), *кузница* (быстрее постройка, лечение) или *наёмники* (новый юнит в панели покупки). |
| **База — тоже условие победы** | Захватили вражескую базу — игрок выбыл из матча, а его золото ушло к вам. |
| **Экономика под огнём** | Золото капает пассивно, быстрее — за флаг и за каждую захваченную базу; опыт уходит в древо прокачки из пяти веток. |
| **Боты как настоящие игроки** | Пять характеров × четыре уровня сложности и явная модель обзора — бот знает только то, что видит. |

### Цикл матча

1. **Лобби** — занимаете слот, добиваете свободные ботами, выбираете сложность и характер.
2. **Отсчёт** — спавн на своей базе, первые юниты покупаются в зоне закупки.
3. **Напор** — берёте центральный флаг, по дороге снимаете аванпосты, тратите опыт на прокачку.
4. **Давление** — рейд на чужую базу выбивает соперника из матча; своя держится армией.
5. **Итог** — побеждает самое долгое удержание флага, спорные случаи решает цепочка тай-брейков.

## 🎮 Управление

| Ввод | Действие |
|---|---|
| `W` `A` `S` `D` | Движение · `Shift` бег · `Space` прыжок |
| **ПКМ** | Удар |
| **ЛКМ** | Отправить приказ в точку под курсором |
| `1` `2` `3` `4` | Стоять · За мной · В атаку · Защита |
| `Z` `X` `C` | Квадрат · Клин · Линия |
| `Tab` | Древо прокачки |
| `B` | Пресеты армии |
| `G` | Гарнизон на своей точке |
| `Left Alt` *(зажать)* | Освободить курсор: можно ткнуть в HUD, камера стоит |

> Приказ **«Защита»** — это не просто «стоять на месте»: пока щит поднят, удар во фронтальный сектор
> гасится, а во фланг и в спину проходит полностью. У приказов есть контрприёмы, в этом и смысл.

## 🚀 Запуск

**Что нужно**

- **Unity 6000.4.3f1** — открывайте ровно этой версией, [Unity Hub](https://unity.com/download) предложит её поставить
- **Git LFS** — один архив в `Assets/ModularRPGHeroesPolyArt/` лежит в LFS
- Основная платформа разработки — Windows; сборка Steam-ассембли также собирается под macOS и Linux

```bash
git lfs install
git clone https://github.com/AdiletJienaliev/O1.git
cd O1
```

Откройте папку через Unity Hub и загрузите сцену `Assets/_InternalAssets/Scenes/Battle_Arena4.unity` —
это игровая арена и единственная сцена в Build Settings.

**Как сыграть матч**

| Цель | Что сделать |
|---|---|
| Быстро проверить в одиночку | В `Configs/GameFlowConfig.asset` включите `skipLobby` — хост поднимется сам, без экрана подключения и лобби |
| Локальный мультиплеер | `backend = Localhost`, хост на `127.0.0.1:7770`, подключение из второго редактора или билда |
| Лобби и приглашения в Steam | `backend = Steam` (или `Auto`) — нужны пакеты Steamworks (см. ниже); в `steam_appid.txt` стоит `480` (Spacewar), стандартный тестовый app id |

> [!IMPORTANT]
> В `Packages/manifest.json` пакет **Heathen Steamworks Complete** подключён локальным путём
> (`file:C:/HeaSteamworks/...`). На свежем клоне такого пути не будет: либо поставьте пакет туда же,
> либо перепишите зависимость на свою копию, либо уберите эту строку и играйте на бэкенде
> `Localhost` — без Steam игра работает полностью.

**Управление живым редактором из терминала** — `Tools/agent/unity.sh` общается с **уже открытым**
редактором: статус, скриншоты, play/stop, логи консоли, клики по UI.
Подробности — в [`Tools/agent/README.md`](Tools/agent/README.md).

## 🧱 Архитектура

Правило, вокруг которого собран весь код: **решает сервер, клиент показывает.** Клиент шлёт намерение,
сервер проверяет его по правилам и реплицирует результат — пути, где клиент сам меняет состояние
матча, просто нет.

<p align="center">
  <img src="docs/architecture.svg" alt="Слои: серверные системы и чистые правила с одной стороны, презентация и UI — с другой" width="100%">
</p>

| Слой | Пространство имён | Что внутри |
|---|---|---|
| **Core** | `Warlord.Core` | Общие перечисления, накопитель фиксированного шага, слоты игроков, раскладка команд. Не зависит ни от чего. |
| **Domain** | `Warlord.Domain` | Правила на чистом C#: расчёт урона, состояние захвата, экономика, оценка победы, построения. |
| **Configs** | `Warlord.Configs` | Баланс в ScriptableObject — режимы, юниты, герои, боты, прокачка. В рантайме не мутируется. |
| **Gameplay** | `Warlord.Gameplay` | Авторитетная симуляция: сетевые компоненты FishNet и серверные системы на такте 20 Гц. |
| **Networking** | `Warlord.Networking` | Поднятие сети через FishNet Multipass, лобби, Steam-транспорт и сессия, лаг-компенсация. |
| **Presentation** | `Warlord.Presentation` | Вьюхи, пул VFX, снаряды, аниматоры, орбитальная камера, цвета команд. |
| **UI** | `Warlord.UI` | Экраны Connect / Lobby / HUD / Result и виджеты — каждый рисует свой кусок состояния. |
| **Editor** | `Warlord.EditorTools` | Редакторные инструменты, сборщики UI и Agent Bridge. |

Ассембли: `Warlord.Runtime`, `Warlord.Steam` (только standalone и редактор), `Warlord.Editor`,
`Warlord.Steam.Editor`. Внедрение зависимостей — **Zenject**, инспекторы — **Odin**.

<details>
<summary><b>Что полезно знать до чтения кода</b></summary>

- **Урон копится, а не применяется сразу.** Два юнита, убивающие друг друга в одном такте, умирают оба.
- **Предсказывается только свой герой.** Юниты интерполируются с задержкой 0.1 с, удары полководца
  валидируются с лаг-компенсацией и перемоткой не более 200 мс.
- **`MatchManager.Instance` — единственная статика в проекте.** Сетевым префабам иначе не раздать
  зависимости; всё остальное разрешается через `IMatchContext`.
- **Обзор ботов смоделирован явно.** Сервер видит всё, поэтому «незнание» пришлось строить руками:
  `Honest` (только свои), `Shared` (плюс союзники), `Omniscient` (честная поблажка верхней сложности).
- **Порядок значений в enum важен.** Всё, что синкается байтом — фаза матча, приказы, улучшения,
  слоты, — обязано сохранять порядок объявления.
- Комментарии в коде на русском и ссылаются на разделы ГДД (`ГДД §N`).

</details>

## 📁 Карта репозитория

```
O1/
├─ Assets/
│  ├─ _InternalAssets/          # всё, что сделано для этой игры

│  │  ├─ Configs/               #   баланс в ScriptableObject
│  │  ├─ Prefabs/               #   юниты, герои, UI, эффекты
│  │  └─ Scenes/                #   Battle_Arena4 — игровая арена
│  ├─ _ExternalAssets/          # сторонние паки графики, эффектов и анимаций
│  ├─ FishNet/                  # сетевая библиотека
│  ├─ Plugins/                  # Odin Inspector, Zenject
│  └─ Settings/                 # ассеты URP
├─ Packages/                    # манифест UPM
├─ ProjectSettings/             # настройки проекта Unity
├─ Tools/agent/                 # CLI-мост к живому редактору Unity
└─ .github/                     # шаблоны задач и пул-реквестов
```

## 📜 Ассеты и права

Код игры в `Assets/_InternalAssets/Code/` — работа этого проекта. Всё, что лежит в
`Assets/_ExternalAssets/`, `Assets/Plugins/`, `Assets/FishNet/` и прочих папках с вендорным
содержимым, — **сторонний контент под своими лицензиями**: паки Unity Asset Store, Odin Inspector,
Zenject, FishNet, Steamworks. Права на их распространение этот репозиторий не даёт: для своего проекта
получайте их из оригинального источника.
